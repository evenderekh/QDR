# QDR Site Architecture

**Qumran Digital Reader** — a static Dead Sea Scrolls reader at [qumran.dev](https://qumran.dev).  
Both biblical scrolls (266) and non-biblical texts (735) with word-level morphological analysis from Abegg's transcriptions.

---

## What It Is

A fully static site — no server, no runtime database. Every page is a self-contained `index.html` baked at build time. Words are hoverable; all morphological parses and lexical definitions are derived at runtime in the browser from two global JS objects (`QDR_LEX` and `QDR_NAV`) loaded as static script files.

## Data Files

### `qdr.1.1.biblical.json` / `qdr.1.1.non_biblical.json`

Top-level array of scroll objects. Each scroll:

```json
{
  "scroll": "1QIsaa",
  "fragments": [
    {
      "id": "1",
      "lines": [
        {
          "n": 1,
          "words": [
            ["surface", "surface_full", "lemma", "morpho", "sp", "ref"],
            ...
          ]
        }
      ]
    }
  ]
}
```

**Word tuple** — 6-element list:

| Index | Field | Description |
|-------|-------|-------------|
| 0 | `surface` | Clean Hebrew glyph (no editorial markers) |
| 1 | `surface_full` | Full glyph with editorial markers: `[ ]` (reconstruction), `#` (damaged), `?` (uncertain) |
| 2 | `lemma` | Pointed Hebrew root (with niqqud) |
| 3 | `morpho` | Abegg morphology code (e.g. `vqp3ms`, `ncmsa`, `Ppo`) |
| 4 | `sp` | Coarse speech part: `verb`, `subs`, `adjv`, `pron`, `ptcl`, `numr`, `suff`, `unknown` |
| 5 | `ref` | `"Book Ch:V"` for biblical scrolls; empty string for non-biblical |

The builder projects each tuple down to 3 elements for the template: `[surface_full, lemma, morpho]`. The template's `cleanHebrewText()` strips editorial markers from `surface_full` for display; the raw value is kept in the DOM for the damage-marks toggle.

**Biblical vs non-biblical:** Biblical scrolls have real verse references in slot 5. Non-biblical scrolls leave slot 5 empty; the builder synthesizes a display reference `"<scroll> <frag_id>:<line>"` for the panel header.

### `qdr.lexicon.json`

Flat object keyed by niqqud-stripped Hebrew root. 4,132 entries, covering 66% of real Hebrew lemmas in the DSS corpus.

```json
{
  "ברא": {
    "strongs_id":  "H1254 — bara",
    "thb_def":     "To create...",
    "strongs_def": "1) to create...",
    "bdb_def":     "(verb) to create..."
  }
}
```

Fields present only when data exists. The template displays whichever field it finds first: `thb_def` → `strongs_def` → `bdb_def`. The unmatched 34%: proper nouns that lack Strong's entries, damaged/partial forms (`#`-noise), and DSS-specific vocabulary with no MT parallel.

## The Extractor: `backend/qdr_extract.py`

**Requires:** Text-Fabric Python library + ETCBC/dss corpus v1.9 at `~/text-fabric-data/github/ETCBC/dss/tf/1.9/`.

Not needed for building the site — only for regenerating the source data from the corpus. The output JSON is committed to the repo.

**Features loaded from TF:** `otype scroll biblical fragment line book chapter verse glyph full lex morpho sp`

**Walk order:** scrolls → fragments → lines → words. The `biblical` feature on the scroll node determines which output file a scroll goes into.

### Fragment / Line Structure

QDR preserves the physical structure of each scroll exactly as ETCBC encodes it — cave → scroll → fragment → line. This is intentional. Earlier approaches to DSS digitization stitched all fragments of a scroll together into a single linear text; QDR does not. Each fragment is a discrete physical object. Lines are numbered within the fragment. Biblical references (where they exist) are attached at the word level, not inferred from fragment structure.

## The Lexicon Builder: `backend/qdr_lexicon_builder.py`

Reads THB's lexicon (`thb/backend/thb.1.3.lexicon.json`) and emits `data/qdr.lexicon.json`.

**Matching strategy:**
1. Load all MT entries from THB lexicon; strip niqqud from `hebrew` field → lookup key.
2. Scan all DSS lemmas from both data files; strip niqqud + `_N` disambiguation suffix + `#` compound prefix → lookup key.
3. Match by stripped key; emit `{strongs_id, thb_def, strongs_def, bdb_def}` for each match.

**Lemma normalization (`clean_lemma`):**
- Strip trailing `_1`, `_2` (Abegg disambiguation suffixes for homographs)
- Take first segment of `#` compounds (morphologically joined forms)
- Strip niqqud via Unicode NFD decomposition, remove `Mn` category characters
- Strip whitespace

Match rate: ~66% of real Hebrew lemmas (those containing at least one Hebrew character). Unmatched remainder: proper nouns (Hebrew has no uppercase so `l[0].isupper()` is always false — all proper nouns land in the "other" bucket), DSS hapax legomena, and damaged/partial forms.

## The Builder: `qdr_builder.py`

Single Python 3 script (~350 lines). stdlib only. All paths are `Path(__file__).parent`-relative.

### Template Placeholders

Five `{{{TAG}}}` substitutions per page:

| Tag | Content |
|-----|---------|
| `{{{SCROLL NAME}}}` | Display name (e.g. `1QIsaa`, `Isaiah`) |
| `{{{PREVIOUS SCROLL LINK}}}` | Relative URL of previous scroll/book (`../1Q6/` or `#`) |
| `{{{NEXT SCROLL LINK}}}` | Relative URL of next scroll/book |
| `{{{HEBREW DATA}}}` | Inline JS: array of verse objects (see below) |
| `{{{NAV CURRENT}}}` | Inline JS: JSON object describing the current page for nav init |

### `{{{HEBREW DATA}}}` Format

Array of verse-block objects baked into each page as a JS array literal:

```javascript
[
  { reference: "Is 1:1", frag: "1:1", words: [
      ["surface_full", "lemma", "morpho"],
      ...
  ]},
  ...
]
```

Non-biblical pages use synthesized references (`"CD 1:1"`) and empty `frag` fields. Book gathered pages prefix each word's frag label with the scroll ID (`"1Qisaa 1:1"`) and insert scroll header entries with `words: []`.

### `{{{NAV CURRENT}}}` Format

```javascript
// Per-scroll page
{ "type": "biblical", "mode": "cave", "cave": "1Q", "scroll": "1Q1", "url": "/biblical/1Q1/" }

// Book gathered page
{ "type": "biblical", "mode": "book", "book": "Isaiah", "url": "/isaiah/" }
```

Used by `initNav()` in the template JS to pre-select the correct dropdowns on load.

### Key Functions

| Function | Purpose |
|----------|---------|
| `group_by_ref(scroll, include_scroll)` | Walk fragment/line/word tree; group words into verse blocks by `ref`; synthesize refs for non-biblical |
| `hebrew_data_js(verses)` | Serialise verse blocks to inline JS array literal (avoids `JSON.parse` overhead) |
| `fill_template(template, ...)` | String-replace all 5 placeholders; returns complete HTML |
| `render_scroll_page(scroll, kind, prev, nxt, template)` | Render one per-scroll page; write to `public_html/{kind}/{sid}/index.html` |
| `collect_book_data(bib_scrolls)` | Aggregate all biblical scrolls by book code; return `{book: [(scroll_name, [verses])]}` |
| `render_book_page(book, scrolls_in_book, template)` | Render gathered view: scrolls in natural order, verses in canonical order within each scroll; header entries separate scrolls |
| `build_nav_data(...)` | Build the `QDR_NAV` tree: caves → scrolls for both types, books list for biblical |
| `write_nav_js(nav_data)` | Serialise `QDR_NAV` → `public_html/static/nav.js` (47 KB) |
| `write_lex_js()` | Serialise `QDR_LEX` → `public_html/static/lex.js` (1.05 MB) |
| `write_sitemap(paths)` | Write `public_html/sitemap.xml` (1,032 URLs) |
| `wipe_output()` | Remove generated dirs/files; preserve `static/`, `about/`, `privacy/`, `terms/`, `index.html` |

### Page Types

| Type | Count | URL pattern | Prev/next |
|------|-------|-------------|-----------|
| Per-scroll biblical | 266 | `/biblical/{id}/` | Adjacent scroll in sorted order |
| Per-scroll non-biblical | 735 | `/non_biblical/{id}/` | Adjacent scroll in sorted order |
| Gathered book | 31 | `/{slug}/` | `#` (no prev/next) |
| Root | 1 | `/` | Copy of `biblical/1Q1/index.html` |

Scroll sort order: `natural_key()` — numeric segments sort numerically, alphabetic segments sort case-insensitively. So `1Q1 < 1Q2 < ... < 1Q72 < 1Qisaa < 2Q1 < ...`

### Build Sequence

```
1. Load template
2. Load biblical + non-biblical JSON
3. Sort scrolls by natural_key
4. For each biblical scroll → render_scroll_page → write
5. For each non-biblical scroll → render_scroll_page → write
6. Aggregate book data → for each of 31 canonical books → render_book_page → write
7. Build QDR_NAV tree → write nav.js
8. Load lexicon → write lex.js
9. Write sitemap.xml
10. shutil.copy2(biblical/1Q1/index.html → index.html)
```

Full rebuild: ~2.3s, 1,032 pages.

**`--scroll ID`** flag: builds a single scroll page only (fast iteration). Does not regenerate nav.js, lex.js, or sitemap.

**`--no-wipe`** flag: skips the wipe step. Useful for incremental adds; stale pages from renamed/removed scrolls will linger.

## The Template: `template/qdr_template.html`

Single HTML file (~1,400 lines). All CSS and JS inline. Two external dependencies loaded at runtime: Cinzel + Inter from Google Fonts, and `/pagefind/pagefind.js` (loaded dynamically on search open).

### Static Assets Loaded at Page Start

```html
<script src="/static/lex.js"></script>   <!-- QDR_LEX global, 1.05 MB -->
<script src="/static/nav.js"></script>   <!-- QDR_NAV global, 47 KB -->
```

Both are loaded synchronously before the page's inline script runs.

### Fonts

Three Hebrew fonts, loaded via `@font-face`:

| Font | File | Script |
|------|------|--------|
| `QumranScroll` | `4Q416jan.ttf` | Qumran scribal hand approximation |
| `QumranPaleo` | `QUMRAN.ttf` | Paleo-Hebrew (Phoenician-derived) |
| `QumranModern` | `noto-sans-hebrew.woff2` | Modern square Hebrew |

The three-way toggle sets a CSS class on `<body>` (`font-scroll`, `font-paleo`, `font-modern`) and switches the `font-family` on `.hebrew-word`. Preference is persisted to `localStorage`.

**Tetragrammaton in Scroll mode:** Words whose `surface_full` is `יהוה` (or unpointed `יהוה`) are detected by `cleanHebrewText()` and given the class `tetragram`, which applies `font-family: QumranPaleo` regardless of the active font mode.

### `cleanHebrewText(text)`

Strips editorial markers from `surface_full` for display. Markers:

| Marker | Meaning |
|--------|---------|
| `[…]` | Reconstructed text |
| `#` | Damaged/illegible |
| `?` | Uncertain reading |
| `ε` | Editorial (Greek epsilon, marks scribal corrections) |

The raw `surface_full` value is kept in `data-word` attributes and used by the damage-marks toggle to show/hide reconstruction brackets.

### `{{{HEBREW DATA}}}` → Runtime Rendering

The inline JS array is assigned to `const SCROLL_DATA = [...]` at page load. `renderScroll()` walks it:

1. Group verse blocks by reference, render each as a `<div class="verse-block">`.
2. Each word becomes a `<span class="hebrew-word">` with `data-lemma` and `data-morpho` attributes.
3. Empty-word blocks (scroll headers in book pages) render as `<div class="scroll-divider">`.

### Navigation (`QDR_NAV`)

Structure:

```javascript
QDR_NAV = {
  biblical: {
    caves: { "1Q": [{id:"1Q1", url:"/biblical/1Q1/"}, ...], "2Q": [...], ... },
    books: [ {name:"Genesis", url:"/genesis/"}, ... ]   // 31 entries, canonical order
  },
  non_biblical: {
    caves: { "1Q": [...], "4Q": [...], ... }
  }
}
```

Navigation has two modes: **Cave** (browse by physical cave: 1Q, 2Q, 4Q...) and **Book** (biblical only — canonical book gathered views). A third dropdown level selects the individual scroll within the cave.

`{{{NAV CURRENT}}}` is read by `initNav()` to pre-select all three dropdowns on page load. If `selectUrl` is null (e.g. user just changed the cave), a placeholder `—` option is inserted so the first real scroll remains selectable.

### Linguistic Panel

Triggered by `mouseover` / `click` on `.hebrew-word` via event delegation from `document`.

**Hover:** `mouseover` calls `showPanel(word)`. `mouseout` dismisses only when `relatedTarget` is outside the word element — prevents false dismissals when the mouse crosses from `.hebrew-word` to a child `<span>` inside it.

**Lock:** `click` on a word locks the panel (gold border, `×` close button visible). Escape or click-outside unlocks. Panel is unlocked on any new hover while locked, then re-locked on the new word if clicked.

**Panel population (`populatePanel`):**

1. `cleanHebrewText(surface_full)` → h3 display word.
2. `lexLookup(lemma)` → looks up `QDR_LEX` using `stripNiqqud` + `clean_lemma` normalization. Returns entry or null.
3. Source label in lemma row: `'THB'` if `thb_def`, `"Strong's"` if `strongs_def`, `'BDB'` if `bdb_def`.
4. Definition text: first available in priority order THB → Strong's → BDB.
5. `parseMorpho(morpho)` → morph object → `morphToHTML()` → key/value grid.

### Morphology: `parseMorpho(code)`

Decodes Abegg morphological codes to a structured object. No abbreviations — all field values are written out in full.

**Code structure:** `{POS_char}{stem?}{aspect?}{pgn...}[X{suffix_pgn}]`

The `X` separator marks the boundary between the word's morphology and its pronominal suffix.

**POS dispatch by first character:**

| Char | POS | Additional fields parsed |
|------|-----|--------------------------|
| `v` | Verb | stem (char 2) + aspect (char 3) + PGN from char 4+ |
| `n` / `u` | Noun (or Proper noun if sub[0]=`p`) | PGN from sub[1]+, state from sub[3/4] |
| `a` | Adjective | PGN from main[1]+, state from main[3] |
| `p` | Pronoun | pronType from sub[0], PGN from sub[1]+ |
| `P` | Particle | type from PART_TYPES lookup on main[1] |

**`parsePGN(s)`** — decodes person/gender/number substring:

| Chars | Values |
|-------|--------|
| Person | `1`/`2`/`3` → `'1st'`/`'2nd'`/`'3rd'` |
| Gender | `m`→`Masculine`, `f`→`Feminine`, `c`/`b`→`Common` |
| Number | `s`→`Singular`, `p`→`Plural`, `d`→`Dual` |
| Mood | trailing `j` → `Jussive` |

**Verb stems** (both Hebrew and Aramaic dialects):

| Code | Stem | Code | Stem |
|------|------|------|------|
| `q` | Qal | `d` | Peal (Aramaic) |
| `N`/`n` | Niphal | `f` | Pael |
| `p` | Piel | `k` | Aphel |
| `P` | Pual | `e` | Ethpeel |
| `h` | Hiphil | `i` | Ithpeel |
| `H` | Hophal | `l` | Ithpaal |
| `t` | Hithpael | `m` | Haphel |
| `v` | Polel | `s` | Shafel |

Aramaic stems appear in non-biblical scrolls where the Abegg transcription marks Aramaic passages.

### `lexLookup(lemma)`

```javascript
function lexLookup(lemma) {
    if (!lemma || typeof QDR_LEX === 'undefined') return null;
    const clean = stripNiqqud(lemma.replace(/_\d+$/, '').split('#')[0].trim()).trim();
    return QDR_LEX[clean] || null;
}
```

Mirrors `clean_lemma()` in the Python lexicon builder: strip disambiguation suffix, take pre-`#` segment, strip niqqud. Returns the full entry object or null.

### Search (Pagefind)

The search button (fifth control in the nav header) opens a popup above the footer. On first open, `import('/pagefind/pagefind.js')` is called dynamically — avoids loading the 300KB+ index on pages where search is never used.

Query → `pf.search(q)` → up to 8 results rendered as title + excerpt links. Graceful fallback message if the Pagefind index is absent (i.e. before `npx pagefind` has been run against the site).

## Known Caveats

- **`lex.js` coverage 66%.** The unmatched 34% are proper nouns without Strong's entries, damaged forms, and DSS-specific vocabulary. The panel shows no definition for these words — the morphological parse still works.
- **Aramaic vocabulary.** Some non-biblical scrolls contain Aramaic passages. The morpho decoder covers Aramaic verb stems but the lexicon (being Hebrew-only from THB/Strong's/BDB) will not match Aramaic lemmas.
- **`l[0].isupper()` proper noun detection is always false.** Hebrew has no uppercase. The lexicon builder's proper-noun heuristic is a no-op; all proper nouns fall into the "DSS-specific / no match" bucket. This is cosmetic (affects the coverage report only, not the lexicon itself).
- **Non-biblical refs are synthesized.** The format `"CD 1:1"` in the panel is `scroll fragment:line`, not a real chapter/verse. For the Damascus Document and similar texts that do have scholarly chapter/verse conventions, the numbering may not match standard critical editions.
- **Gathered book pages have no prev/next.** Navigation arrows render as `#` on book pages. This is intentional — there is no meaningful "next book" scroll in the biblical gathered view.
- **`--no-wipe` leaves stale pages.** If a scroll is renamed or removed from the source data, its old `index.html` will persist in `public_html/` until a full wipe-and-rebuild.
- **`SITE_BASE` is empty.** Sitemap URLs are path-only until the domain is set in `qdr_builder.py`.
